# Task 2.3 — Computers and isolated SSH test

Scope: `redesign-xmouse-ng` task **2.3 [high]**, 2026-10-25. No other task implementation, staging, commit, push, archive, signing-key access, ADB, or real-user database/vault operation was authorized or performed.

## Integration contracts for the following tasks

- `ComputerEditorActivity.intent(Context, long)`: IDs greater than zero edit an existing computer; zero opens a new form. Intent extras contain metadata only. Use `MainActivity.openExternalScreen(...)` from the shell so `ShellNavigation.EXTERNAL` retires control-input ownership before leaving; returning retains the existing foreground-service session.
- `ComputerEditorActivity.discoveredIntent(Context, Candidate)`: opens the same full-height View/XML form with the actual service locator and advertised SSH port. It deliberately does **not** pass observed DHCP addresses or save/select/connect anything. A service-only locator can keep its endpoint field blank, with an explicit service-resolution explanation; changing the endpoint makes it a manually entered endpoint.
- Header Computers offers actual saved selection/connect, per-row Edit and endpoint/port details, Add, Find, management, and the existing snapshot-driven Connect/Disconnect/Retry. `ListEditActivity` remains the real NSD/permission/lifecycle bridge (`findComputers=true` opens Find). Its ordinary host Add/Edit/Find routes now launch the full-screen form. Its script route (`intVariableType=1`) and CRUD are unchanged; retained legacy dialog APIs are hardened against password prefill/blank erasure and unconfirmed host deletion.
- `CredentialRepository.updateHostMetadata(expected, alias, endpoint, user)`: explicit unchanged-password edit. Validates the account, checks the expected metadata snapshot, and updates non-secret columns only. It does not call `prepare`, decrypt/read/write a secret, replace an opaque reference, migrate/import credentials, clear backup/re-entry flags, or edit selection/authentication preferences. Nonblank replacement continues through the existing verified-new-record/SQLite publication path.
- `authenticationSelection(candidate)` captures global authentication choices without selecting the candidate. `authenticateProbe(selection, replacement, prompts, callback)` reads production protected material or uses an in-memory replacement. Null replacement means the captured saved reference; an explicit empty array is a new form's empty password. It never imports a legacy private-key path, calls Save/migration, resets credentials, or changes global authentication preferences. Existing protected-key/passphrase validation and attempt-only re-entry remain authoritative; unavailable legacy material gets a sanitized error and a Settings link.
- `ConnectionProbe` is a serial, weak-observer, attempt-only owner over `SshSessionAttemptFactory`. It exposes no command API. Its candidate must have an empty custom shell and null initial command. Results wait for confirmed physical close; cleanup uncertainty blocks further tests in that form. Generation/identity checks reject late phases/readiness/results. Cancellation retires unclaimed password bytes immediately and waits for bounded cleanup before another candidate is allowed.
- `AndroidComputerProbe` composes separate interactions, transport/backend/trust owners, the production Android address resolver, and protected credential provider. It never uses/replaces the service controller or its active SSH transport. Settings should continue to own the real **global** key/passphrase/authentication choices; there is no new per-computer key mode.

## Privacy and behavior choices

- Persistent Material labels, password visibility toggle, actual Advanced port (new default 22), optional display name, inline required endpoint/account/port validation, and rejection—not trimming—of leading/trailing username whitespace. Invalid Save/Test stays open without touching stored values.
- An existing password field is always blank. Blank Save preserves the exact protected reference, ciphertext, legacy/re-entry state, and backup markers, including when the key is unavailable. No password is decrypted merely to display a form. Save performs secret I/O off the UI thread; a deliberate Save already submitted may finish after leaving, but its callback cannot close/update a later form.
- Password widgets disable saved state and autofill; only an explicit allow-list of non-secret form metadata is bundled for recreation. Password text is cleared on stop. Pending permission/trust/credential interactions and probes are cancelled on stop or form change. The editor uses `FLAG_SECURE` to keep secret fields out of screenshots/recents. An external key picker also causes stop/cancellation; re-importing durable material remains a separate Settings operation.
- Unknown host keys require explicit fingerprint approval before SSH user authentication. That explicit approval may save the approved public key through the existing trust repository; it does not save the computer/credential candidate. Changed keys are blocked, not replaced by Test; deliberate trust replacement remains in the existing normal connection review flow.
- Success means real authentication plus shell-channel readiness, followed by confirmed close. No configured custom shell, initial command, script, shell-input write, or exec command is submitted by Test. Its shell channel's output is discarded. Failure messages use typed safe categories, not remote/provider messages or input values.
- Focused verification exposed a pre-existing channel-timeout classification race: JSch's own timer could beat the coordinator timer and yield generic `CONNECTION`. `SshBackend.ChannelSetupException` now carries only timeout-versus-rejection metadata; `JschSshBackend` classifies by monotonic elapsed time (one millisecond of provider clock rounding), and `SshTransport` reports `CHANNEL_TIMEOUT` versus `CHANNEL_CLOSED`. Bounds, trust/authentication, and message/logging policy are unchanged. The retained loopback deadline regression and a new typed-outcome test cover both sides.
- Existing production bounds apply: up to 60 seconds for protected credential acquisition, a 90-second SSH connection budget (including a maximum 60-second trust decision), and a maximum 5-second attempt-close barrier. Transport sub-operations remain individually bounded and use the existing process-wide capacity/quarantine controls.
