# Task 2.4 — native Actions, profiles, and saved scripts

Scope: `redesign-xmouse-ng` **2.4 [low]**, 2026-10-25. The recorded user-approved routing exception authorizes `openai/gpt-6.1-sol#xhigh` for this task and its verification; the complexity tag is unchanged.

## Implemented contracts

- `MainActivity` now renders the selected **saved** repository profile as rounded two-column native tiles, with explicit Edit/Done, real ID-addressed layout selection, Add action, More → named-layout management / Advanced editor, and actual saved-script entries. Names may duplicate, catalog order is retained, and there is no three-profile limit. The old ten-column View grid is an inaccessible zero-height compatibility adapter, not the primary Actions surface.
- `ActionsViewRenderer` is shared by production and the isolated debug layout fixture, including the real ID-based native profile picker and Edit/Done controls. Tiles contain an icon, title, shortcut/Advanced subtitle, and a Custom-span disclosure. Stored RGB/ARGB colors are not converted; foreground contrast is chosen for the rendered color.
- `ActionEditorActivity.intent(context, profileId, buttonId?)` opens a full-height, scrollable, inset/IME-aware native form. New actions default to Keyboard shortcut, Regular **5**, and the existing default color. Wide is **10**. Presets do not modify untouched custom widths/colors. Existing Custom widths are disclosed and remain accessible in the full Advanced ten-column editor; custom RGB is optional. Add/Save, Cancel, and separately confirmed Delete never execute input. Raw SSH creation has an explicit **Create SSH script** route, not silent custom-button reinterpretation.
- `ActionCommandCodec` recognizes only exact `key CHORD` / `xdotool key CHORD` single-chord forms. Flags, unusual spacing, multiline text, and unknown commands remain opaque Advanced text. An untouched canonical shortcut keeps its original raw prefix and bytes; an untouched Advanced command keeps every byte. Newly entered `Alt+F4` serializes to `key Alt+F4` and goes through `IDoTool.key`, not raw shell execution. `CustomCommandDispatcher` itself is unchanged: only its leading `xdotool ` prefix is removed; `key` still consumes the first following token; the raw-shell fallback is unchanged.
- `ActionEditorSessionViewModel` delegates all validation/draft/atomic Save/Delete work to the existing `LayoutEditorViewModel` and `LayoutProfileRepository`. A pre-existing recovery draft is never overwritten by the simple form: it routes to Advanced review. Failed publication leaves the last saved profile and recoverable draft intact, with explicit Retry save. Merely opening/cancelling a form writes no draft. Rotation-only form text lives in the retained ViewModel, not Android saved-state bundles; process death can discard unsaved form text safely.
- `LayoutEditorWorkerViewModel` and `LayoutProfileManagerWorkerViewModel` serialize the existing Advanced editor/history and named-profile manager operations off the main thread. They retain no Activity, View, transport, SSH, or command-execution sink. Their domain view models remain the repository/draft/history authorities. Named-profile activation also works after deliberate deletion of the initial empty profile when no retained source requires migration recovery.
- Main profile activation/migration, listing, selection, reload, and explicit legacy preset operations use the existing `LayoutProfileRuntime`/repository on the Actions I/O worker. `ShellNavigation.replaceContent` retires old gestures **before** replacing controls, then renders and refreshes eligibility. Normal tiles use the existing Actions-role surface and captured DOWN/UP/accessibility capability path; detached/stale tiles cannot borrow a newer surface. Edit owns `ACTION_EDIT`, external forms/managers own `EXTERNAL`, and editing disables command execution without disconnecting the service session. Back exits Edit correctly.
- `SavedActionScriptRepository` lists real IDs/names from the existing SQLite `scripts` table and loads raw command text only for deliberate Run. Run uses the existing `SessionCommandTransport.executeExecCommand` / `SessionActivityPresenter` result route, separate from input dispatch. Late script lookups are rejected after navigation, surface retirement, editor opening, lifecycle loss, or recreation. No script preview/selection/edit executes it.
- Script Add/Edit opens the existing `ListEditActivity` CRUD route with `EXTRA_ADD_SCRIPT` / string-valued `EXTRA_SCRIPT_ID`. Script SQLite work is serialized off the UI thread using application context and weak screen callbacks; Save reports failure instead of claiming success, and Delete requires separate confirmation. `DatabaseHandler.addScript` uses the existing table/columns with a checked insert; schema/version/host columns are unchanged. The native script form has persistent labels, multiline raw SSH input, and 48dp minimum fields.
- A genuinely new installation receives one empty Actions profile and no example actions/scripts. Existing profiles and retained legacy files always win. An upgrade with pre-existing database/preferences but no saved layout source preserves the old built-in fallback buttons under stable IDs instead of erasing the old default grid. The first-launch classification survives Activity recreation. No reference example data is seeded, and no retained source file is rewritten.

## Deliberate presentation choices

- The two-column presentation buckets legacy widths **1–9** into one visual cell and width **10** into a full row. All original ten-unit spans remain byte/value-exact in storage; non-5/10 widths are labeled Custom and can be changed precisely in Advanced. This is display bucketing, not a migration.
- The simple action editor is a full-height native form rather than a small bottom sheet; size choices stack vertically and color presets scroll horizontally so labels remain reachable at narrow widths/enlarged fonts. It does not require numeric columns or hex colors for ordinary new actions.
- Full ten-column preview/reorder, accessible earlier/later movement, duplication, Undo/Redo, drafts, and history remain in More → Advanced editor. A new raw SSH script uses the existing script editor/result path. Switching from an unsaved simple form to another editor cancels that local form, as its help text states.
- The legacy-source migration gate remains fail-closed on malformed/unreadable sources. Files and profiles are retained, not silently replaced with an empty/demo layout.

## Following-task integration

- Settings work remains **2.5**, not part of this change. Continue using `MainActivity.openExternalScreen(...)` for external settings/forms, `shellNavigation()` for shell transitions, and the existing role-specific input tokens. Do not connect/disconnect merely to change UI surfaces. Computers/probe/credential APIs from `redesign-task-2.3.md` and clipboard export are unchanged.
- `MainActivity.selectedSavedActionProfile()` is a read-only immutable saved snapshot; `refreshSavedActions()` requests a safe asynchronous reload. Never use a draft/preview as the executable normal profile. Main selected-profile changes must continue through `LayoutProfileRuntime`, not alternate JSON/catalog writers.
- For scripts, pass the stable SQLite ID as a **String** in `ListEditActivity.EXTRA_SCRIPT_ID`, or `EXTRA_ADD_SCRIPT=true` for Add. Normal raw SSH scripts must remain exec operations; do not pass them through `CustomCommandDispatcher`.
- Existing instrumentation coverage now targets actual native tiles rather than trying to click the hidden legacy adapter. Runtime execution of those tests is still a separate gate; asynchronous editor operations require eventual-state waits rather than assumptions that Compose idleness alone means disk work finished.
