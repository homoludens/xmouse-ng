This crosswalk originally accounted for the 50 scenarios audited by task 11.7. Task 10.7 adds

not a claim that it passed. Task IDs below refer to
[`tasks.md`](../../openspec/changes/modernize-xmouse/tasks.md). Test-class names identify evidence,
not a promise that an Android test ran.

## Evidence and status rules

- **Current JVM pass** means the listed host-side tests passed against the current code in task 11.1's
  403-test run, or in the task-specific JVM run cited in tasks 6–9. It can prove model, fake, or
  loopback behavior; it does not prove Android UI, device, LAN, or live-host behavior.
- **Build/compiled-only** means Android UI/instrumentation code was compiled by the cited task; it was
  not executed. Task 11.1 did not rebuild the AndroidTest APK.
- **Historical API 26/35 only** means an actual test ran on an earlier task-specific APK at the named
  API level(s). It is not runtime evidence for the latest integrated code. API 35-only evidence is
  identified as such.
- **NOT RUN/device/LAN** means the required current-device, physical-device, or live-LAN scenario was
  not executed. APK compilation and JVM fakes are not runtime passes.
- **Implementation gap** means the described user-visible behavior is not available in the current
  implementation, regardless of repository APIs or tests.

Task 11.1 anchors the current whole-suite evidence: with both `ANDROID_HOME` and `ANDROID_SDK_ROOT`

This crosswalk does not rerun that suite. See task 11.1 in `tasks.md`.

Current integrated-code device/API and live-LAN gaps are anchored to tasks 6.5, 10.1–10.4, and
11.2–11.5 and [`android-platform-coverage.md`](android-platform-coverage.md): current API 26, 31,

and current device integration are **NOT RUN**. Task 6.5's one-lookup socket ownership and cleanup

## Open runtime verification and task 11.7 decision

1. **Task 6.5 runtime verification remains open, not an implementation gap:** the one-shot legacy-unicast
   fallback owns one ephemeral socket for one lookup and closes it on completion, cancellation, timeout, and
   failures; the 62 focused resolver/codec/session JVM tests passed (see [mdns-fallback.md](mdns-fallback.md)).
   No multicast group membership/listener is used, and a Wi-Fi `MulticastLock` is not required for unicast
   replies. Task 6.5 remains unchecked because API 26 device socket behavior and real VPN/network-policy
   behavior are **NOT RUN**; the JVM evidence is not a device pass.
2. **Device/LAN acceptance remains outstanding:** tasks 11.2–11.5 are explicitly **NOT RUN**. Historical API
   26/35 emulator tests do not cover the latest integrated code, API 31/33/34/36/37, the physical five-minute
   continuity check, or live LAN/discovery. See [android-platform-coverage.md](android-platform-coverage.md).

**Decision:** the original task 11.7 audit mapped 50/50 scenarios and found no unresolved implementation gap. The later task 10.7 scope adds three scenarios; task-specific JVM/build evidence is recorded above and in `tasks.md`. Android UI/device clipboard acceptance remains **NOT RUN** and is not represented as a runtime pass.
The profile-manager implementation is present; task 6.5 and tasks 11.2–11.5 remain open only for clearly
identified device/API/LAN verification, which is **NOT RUN**, not passed. With strict validation successful,
task 11.7 is complete; this does not complete or alter any open device-verification task.
